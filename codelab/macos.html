Qué vas a construir

Una app nativa de macOS de tareas, ejecutada directamente en la Mac. Vas a reutilizar ideas de SwiftUI y descubrir ventanas, menú de la app y atajos de teclado. Este laboratorio no necesita iPhone, runtime de simulador ni Apple Account.

Usa Xcode 27.1 y macOS compatible con esa instalación; el proyecto apunta a macOS 14 o posterior. Todo usa frameworks incluidos en Xcode. La guía y la app funcionan offline; GitHub requiere internet.

La lista, agregar desde +, completar, borrar y el formulario ya funcionan. Al inicio, Archivo → Nueva tarea no abre el formulario y no tiene ⌘N: eso lo completarás tú. El estado es en memoria; salir de la app restaura los ejemplos.

Tu trabajo: editar dos archivos, probar el menú y el teclado, guardar dos commits y abrir un PR con captura. No tienes que portar toda la app de iOS ni resolver firma para distribución.

Tu rama y la primera ejecución

Antes de empezar: Xcode debe estar preparado y debes tener una copia de tu fork, acceso a GitHub y tu segundo factor. Si es una Mac distinta, vuelve a clonar tu fork y configura tu identidad local siguiendo la guía del primer día. El token del día anterior probablemente ya venció: genera uno nuevo solo cuando vayas a hacer push.

En Terminal, entra en tu copia de TODOiOSLab y comprueba que no tienes cambios sin guardar:

git status
git remote -v

Si git status muestra cambios pendientes, guarda tu trabajo con un commit en tu rama anterior antes de continuar. Si no sabes a qué ejercicio pertenecen, pide ayuda. No uses reset ni descartes archivos. origin debe apuntar a tu cuenta.

Obtén la rama del docente explícitamente; esto funciona aunque tu fork o clon solo tuviera main. Crea una rama nueva desde esa referencia. Sustituye tu-alias por tu nombre sin espacios:

# Descarga la rama de este laboratorio del repositorio del docente.
git fetch https://github.com/franzueto/TODOiOSLab.git lab-macos
# FETCH_HEAD es la rama que acabas de descargar. Ejecuta este paso a continuación.
git switch -c lab/macos-tu-alias FETCH_HEAD
# Abre el proyecto del laboratorio.
open macOS/TODOMacLab.xcodeproj

Conserva el remoto origin apuntando a tu fork; allí subirás tu rama de trabajo.

Este laboratorio parte de una base preparada, no de los cambios que hiciste en tu rama del primer día. Tus cambios anteriores siguen guardados en esa rama; aquí vuelve a personalizar tu app. Si ya usaste el nombre de rama propuesto, usa uno nuevo, por ejemplo con sufijo -2.

  1. En Xcode selecciona esquema TODOMacLab y destino My Mac.
  2. ⌘R ejecuta la app de escritorio. Haz clic en la ventana: la barra de menús de macOS cambia al menú de tu app.
  3. Usa + en la barra de la ventana, escribe una tarea y pulsa Guardar. El círculo permite completarla y la basura borrarla.
  4. Abre Archivo/File → Nueva tarea. Al inicio no hace nada: ese es el ejercicio.

⌘1 muestra archivos y ⌘5 muestra errores. Abre el proyecto de macOS/, no el proyecto iOS de la raíz. La firma local está preparada como Sign to Run Locally; no selecciones un Team ni configures distribución.

Comprueba: la app corre en una ventana de macOS y + abre un formulario con Guardar y Cancelar.

1 · Personaliza la ventana

Abre macOS/TODOMacLab/LabSettings.swift. En MAC 1, cambia las tres constantes; utiliza tu alias, no el ejemplo:

static let ownerName = "Andrea · Mac"
static let accentColor: Color = .orange
static let symbolName = "star.circle.fill"

let es constante; static permite leer estas opciones mediante LabSettings.ownerName. El símbolo y el color vienen con el sistema. Prueba también .purple o .teal.

En TODOMacLabApp.swift, cambia solamente los números de defaultSize:

.defaultSize(width: 820, height: 560)

Son puntos de tamaño inicial, no una restricción fija. Puedes redimensionar la ventana arrastrando sus bordes; el mínimo ya está preparado. macOS puede recordar el tamaño de una ventana anterior: si no ves el nuevo tamaño al relanzar, eso no implica que tu cambio sea incorrecto. Comprueba también el redimensionamiento manual.

Guarda y ejecuta con ⌘R. Tu alias debe aparecer en el título y en la cabecera.

git add macOS/TODOMacLab/LabSettings.swift macOS/TODOMacLab/TODOMacLabApp.swift
git commit -m "Personaliza mi app nativa de macOS"

Comprueba: ves tu alias, el color y el símbolo. Puedes ensanchar la ventana y la lista se adapta.

2 · Conecta el menú Nueva tarea

En TODOMacLabApp.swift, busca MAC 2. Agrega una línea dentro de la acción del botón:

Button("Nueva tarea") {
    isPresentingNewTodo = true
}

No reemplaces el archivo completo ni borres .disabled(...). La variable @State ya existe en el punto de entrada de la app. Al ponerla en true, la ventana muestra el formulario. El botón + usa ese mismo estado, por lo que ambos caminos hacen lo mismo.

En TodoScreen, @Binding permite leer y modificar ese estado recibido; el prefijo $ entrega esa conexión. .sheet presenta el formulario. No necesitas editar esos componentes preparados.

CommandGroup(replacing: .newItem) coloca nuestro comando en el grupo del menú Archivo/File destinado a crear elementos. Sustituimos el comando predeterminado para evitar competir con Nueva ventana.

Ejecuta, activa la ventana de tu app y usa Archivo/File → Nueva tarea. Escribe “Mi tarea desde el menú” y guarda.

Comprueba: el menú abre el mismo formulario que + y la tarea aparece una sola vez. Si ves los menús de Xcode, activa primero la ventana de tu app.

3 · Agrega ⌘N

Busca MAC 3 en el mismo archivo. Entre el cierre del botón y .disabled, agrega:

.keyboardShortcut("n", modifiers: .command)

El grupo completo queda así:

CommandGroup(replacing: .newItem) {
    Button("Nueva tarea") {
        isPresentingNewTodo = true
    }
    .keyboardShortcut("n", modifiers: .command)
    .disabled(isPresentingNewTodo)
}

El atajo llama la misma acción del botón del menú. .disabled evita pedir otro formulario cuando ya hay uno abierto. En macOS un atajo actúa en la app que está activa, no en todas las apps.

Ejecuta y haz clic en tu ventana. Pulsa ⌘N, escribe una tarea y pulsa Return. El formulario ya tiene Guardar como acción predeterminada. Vuelve a abrirlo con ⌘N, escribe un borrador y pulsa Escape: debe cancelar sin crear la tarea.

git add macOS/TODOMacLab/TODOMacLabApp.swift
git commit -m "Conecta Nueva tarea al menú y al atajo Command N"

Comprueba: Archivo muestra ⌘N junto a Nueva tarea; el atajo abre el formulario; Return guarda y Escape cancela.

Prueba como usuario de Mac

  • Crear por +, por menú y por ⌘N: los tres caminos funcionan.
  • Formulario vacío o solo espacios: Guardar deshabilitado.
  • Cancelar con botón o Escape: no agrega nada. Volver a abrir: borrador vacío.
  • Guardar con Return: una sola tarea nueva y campo limpio en el siguiente formulario.
  • Con el formulario abierto, Nueva tarea está deshabilitado y ⌘N no abre otra ventana.
  • Completar/reabrir y borrar actualizan el contador.
  • Redimensionar la ventana mantiene los controles visibles.
  • Salir con ⌘Q y ejecutar de nuevo: vuelven los ejemplos; es lo esperado para este laboratorio.

Pregunta: ¿por qué el menú y el botón + pueden abrir el mismo formulario sin duplicar la lógica para agregar tareas?

Captura y entrega

Prepara al menos dos tareas y una completada. Con tu ventana activa, pulsa ⇧⌘4, luego Espacio y haz clic en la ventana para capturarla. Debe verse tu alias. Agrega una segunda captura con Archivo/File abierto y Nueva tarea ⌘N visible; puedes usar ⇧⌘5 con temporizador para abrir el menú antes de capturar. No incluyas credenciales ni otras ventanas personales.

Revisa tus cambios y confirma que tienes al menos dos commits propios de este laboratorio. Si el último paso dejó cambios pendientes, guárdalos antes del push:

git status
git diff --check
git diff
git log --oneline -5
# Solo si quedan cambios tuyos pendientes:
git add macOS/TODOMacLab/LabSettings.swift macOS/TODOMacLab/TODOMacLabApp.swift
git commit -m "Finaliza laboratorio macos"
# Sustituye tu-alias por el mismo nombre usado al crear la rama.
git -c credential.helper= -c core.askPass= push -u origin lab/macos-tu-alias

Si no hay cambios, omite git add y git commit. El push va a tu fork. Para autenticarte usa tu usuario y un token temporal como contraseña; no se muestra al pegar. No pegues el token en la URL, comandos, archivos ni capturas.

Recordatorio de acceso temporal

En GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens, crea un token por un día, propietario tu cuenta, solo tu fork, permiso Contents: Read and write. Configura git config --local credential.helper "" para no guardarlo en el llavero. Si quieres el recorrido completo, consulta la guía del primer día. El token sirve para Git; el PR se crea con la sesión web. No reutilices el token vencido del primer laboratorio.

En GitHub abre tu fork → Pull requests → New pull request. Revisa que base repository sea TU_USUARIO/TODOiOSLab, base sea main, head repository sea tu mismo fork y compare sea tu rama de este laboratorio. Si GitHub propone el repositorio del docente como destino, cámbialo.

El PR contra main también puede mostrar la preparación de este laboratorio, porque partiste de una rama del docente: es esperado. En la descripción distingue tus cambios personales de la base preparada.

GitHub puede rellenar la plantilla del primer día porque la base es main. Abre .github/pull_request_template.md de tu rama actual (por ejemplo, con cat .github/pull_request_template.md en Terminal), copia su contenido y reemplaza la descripción del PR con esa plantilla de segunda sesión. Complétala, arrastra las capturas, espera a que carguen y revisa Preview. Comparte el enlace por el canal del curso y deja el PR abierto. Si aún existe el PR del día anterior, conserva ambos: esta entrega es un PR nuevo.

Antes de salir: verifica que el PR exista, revoca el token de hoy, cierra sesión de GitHub y las ventanas privadas; reemplaza el portapapeles por texto inocuo. Si no hay internet, conserva los commits y la captura: la entrega remota queda pendiente, no inventes un enlace.
